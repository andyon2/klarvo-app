# Story 9.2: History-Backend

Status: review

## Story

Als täglicher Klarvo-User
möchte ich, dass jedes erfolgreiche Diktat automatisch in einer lokalen SQLite-Datenbank gespeichert wird,
damit ich in Story 9.3 (History-Panel) meine Diktat-Geschichte lesen, einzelne Einträge löschen und den Verlauf leeren kann.

## Kontext und Motivation

**Problem:** Klarvo v2 hat noch keine History-Persistenz. Nach jedem Diktat (deliver-success) verschwindet der Text; weder Verlaufsansicht noch Suche sind möglich. Das History-Panel (Story 9.3) setzt einen funktionierenden Backend voraus.

**Backlog-Referenz:** `docs/backlog.md §History-Panel`: "History-Write passiert bereits Phase-1 (7-Step-Topology-Step-7 äquivalent via OutputTarget-Wire-Up-Downstream-Plan). Panel = UI-Surface dafür. SQLite-History-Schema bereits Phase-0/1 geplant."

**Architektur-Entscheidung:** `klarvo-core/src/history/` als Heimat des Traits + SQLite-Impl. Schema: v1-Schema als Baseline + additive Felder (`plugin_id`, `manifest_version`, `output_language`). Migration via PRAGMA user_version (identisches Pattern wie `settings/migrations.rs`). Fail-soft bei Append-Failure — Delivery darf nicht blockiert werden.

**Scope-Grenze:** Nur Backend und Tauri-Commands. UI (History-Panel im Settings-Window) ist Story 9.3. Retention-Policy: `history.max_entries` (Default 500, prune oldest on append). `raw_text` = None in Phase-1 (Pipeline tracked intermediate results nicht separat). `app_name` = None in Phase-1 (HWND→ProcessName wäre weiterer Win32-Call, Epic-9.6-Scope).

```rust
/// A stored dictation history entry (full record, with id).
#[derive(Debug, Clone, PartialEq, serde::Serialize, serde::Deserialize)]
pub struct HistoryEntry {
    pub id: i64,
    pub text: String,
    pub raw_text: Option<String>,
    pub style: String,            // e.g. "verbatim", "polished"
    pub language: String,         // ui_language at time of dictation
    pub app_name: Option<String>, // Phase-1: always None
    pub created_at: String,       // ISO-8601 UTC, e.g. "2026-05-03T10:00:00Z"
    pub uuid: Option<String>,
    pub device_id: Option<String>,
    // Additive v2 fields (architecture.md §History-Schema)
    pub plugin_id: Option<String>,        // STT plugin_id from manifest
    pub manifest_version: Option<String>, // pipeline manifest version
    pub output_language: Option<String>,  // output language axis
}

/// Fields needed to persist a new entry (no id — generated by DB).
#[derive(Debug, Clone)]
pub struct NewHistoryEntry {
    pub text: String,
    pub raw_text: Option<String>,
    pub style: String,
    pub language: String,
    pub app_name: Option<String>,
    pub created_at: String,        // ISO-8601 UTC
    pub uuid: Option<String>,
    pub device_id: Option<String>,
    pub plugin_id: Option<String>,
    pub manifest_version: Option<String>,
    pub output_language: Option<String>,
}

/// Storage backend for dictation history.
///
/// Implementations must be `Send + Sync + 'static` for DI-mockability.
/// All async fns return `AppError` on failure — callers decide whether to
/// surface the error or fail soft.
#[async_trait::async_trait]
pub trait HistoryBackend: Send + Sync + 'static {
    /// Persist a new dictation entry. Returns the new row's `id`.
    /// On `max_entries` exceeded: oldest entries are pruned atomically.
    async fn append(&self, entry: &NewHistoryEntry) -> Result<i64, AppError>;

    /// Load up to `limit` most-recent entries, newest first.
    async fn list(&self, limit: u32) -> Result<Vec<HistoryEntry>, AppError>;

    /// Delete entry by id. Idempotent (no-error on missing id).
    async fn delete(&self, id: i64) -> Result<(), AppError>;

    /// Delete all entries.
    async fn clear(&self) -> Result<(), AppError>;

    /// Total number of stored entries.
    async fn count(&self) -> Result<u32, AppError>;
}

/// No-op implementation for contexts where history is not available.
/// Used as fail-soft fallback when SqliteHistoryStore::open() fails at boot.
pub struct NullHistoryBackend;

#[async_trait::async_trait]
impl HistoryBackend for NullHistoryBackend {
    async fn append(&self, _entry: &NewHistoryEntry) -> Result<i64, AppError> { Ok(0) }
    async fn list(&self, _limit: u32) -> Result<Vec<HistoryEntry>, AppError> { Ok(vec![]) }
    async fn delete(&self, _id: i64) -> Result<(), AppError> { Ok(()) }
    async fn clear(&self) -> Result<(), AppError> { Ok(()) }
    async fn count(&self) -> Result<u32, AppError> { Ok(0) }
}
```



### AC-3: `SqliteHistoryStore` mit Schema-Migration

**Given** `klarvo-core/src/history/mod.rs` existiert (AC-1),
**When** Story 9.2 committed ist,
**Then** existiert `klarvo-core/src/history/sqlite.rs` mit:

```rust
/// SQLite-backed history store.
///
/// Opened via `open(path, max_entries)` for production use or
/// `in_memory(max_entries)` for tests. Schema migration uses PRAGMA
/// user_version — identical pattern to `settings/migrations.rs`.
pub struct SqliteHistoryStore {
    conn: Arc<tokio::sync::Mutex<rusqlite::Connection>>,
    max_entries: u32,
}

impl SqliteHistoryStore {
    /// Open (or create) history.db at `path` and apply schema migrations.
    pub fn open(path: &std::path::Path, max_entries: u32) -> Result<Self, AppError> { ... }

    /// In-memory SQLite for tests — schema migrations applied identically.
    pub fn in_memory(max_entries: u32) -> Result<Self, AppError> { ... }
}
```

**Schema (Migration v1):**
```sql
CREATE TABLE history (
    id               INTEGER PRIMARY KEY AUTOINCREMENT,
    text             TEXT    NOT NULL,
    raw_text         TEXT,
    style            TEXT    NOT NULL DEFAULT 'verbatim',
    language         TEXT    NOT NULL DEFAULT '',
    app_name         TEXT,
    created_at       TEXT    NOT NULL,
    uuid             TEXT,
    device_id        TEXT,
    plugin_id        TEXT,
    manifest_version TEXT,
    output_language  TEXT
)
```

**Migration-Pattern** (identisch zu `settings/migrations.rs`):
- `PRAGMA user_version` lesen → vergleichen → fehlende Migrationen in Transaktionen applizieren
- Downgrade-Guard: `current > max_known` → `AppError { kind: Io, ... }`
- `apply(conn)` ist die einzige Schema-Authority (kein `CREATE TABLE IF NOT EXISTS` in App-Code)

**`append()` Retention-Logic:**
```rust
// Insert new row
conn.execute("INSERT INTO history (...) VALUES (...)", params)?;
// Prune oldest if over cap
if self.max_entries > 0 {
    conn.execute(
        "DELETE FROM history WHERE id IN (
             SELECT id FROM history ORDER BY id ASC
             LIMIT MAX(0, (SELECT COUNT(*) FROM history) - ?1)
         )",
        [self.max_entries],
    )?;
}
```

**`list()` Order:** `ORDER BY id DESC LIMIT ?1`

**`delete()` Idempotenz:** kein Error wenn Row nicht gefunden (0 rows affected ist OK).

**`created_at`-Format:** ISO-8601 UTC. Erzeugung: `std::time::SystemTime::now()` → UNIX-Epochen-Sekunden → manuell als `"YYYY-MM-DDTHH:MM:SSZ"` formatieren ODER via `time`-Crate (transitiv via `tracing-appender`). Der dev agent wählt die sauberste verfügbare Option ohne neue top-level-Dep einzuführen.

**Kein `.unwrap()`/`.expect()` in Production-Code** (disallowed_methods = "deny" in klarvo-core).

`impl HistoryBackend for SqliteHistoryStore` registered in `klarvo-core/src/history/mod.rs`:
```rust
mod sqlite;
pub use sqlite::SqliteHistoryStore;
```

### AC-5: `SessionOrchestrator` injiziert und nutzt `HistoryBackend`

**Given** `klarvo-shell-orchestrator/src/session.rs` hat 11 Konstruktor-Parameter (letzter: `focus_capture`),
**When** Story 9.2 committed ist,
**Then**:

1. `SessionOrchestrator` Struct bekommt neues Feld `history_backend: Arc<dyn HistoryBackend>`.
2. `SessionOrchestrator::new()` erhält neuen Parameter `history_backend: Arc<dyn HistoryBackend>` (nach `focus_capture`).
3. Im `pipeline_task` (Closure): `Arc::clone(&self.history_backend)` als `history_backend`-Variable.
4. **Nach `target.deliver(&text).await` — auf dem Erfolgs-Pfad aller Modi** (vor paste/focus-restore):

```rust
// History-Persistence: fail-soft — delivery must not be blocked
// by a storage write failure (deferred-work candidate if persistent).
let history_entry = NewHistoryEntry {
    text: text.clone(),
    raw_text: None,  // Phase-1: not tracked; pipeline returns only final text
    style: manifest_stt_style(&manifest), // helper: first cleanup stage plugin_id or "verbatim"
    language: String::new(), // Phase-1: output_language not yet passed into orchestrator
    app_name: None,          // Phase-1: HWND→ProcessName not wired
    created_at: wall_clock_iso8601(), // helper: SystemTime::now() → ISO-8601
    uuid: None,
    device_id: None,
    plugin_id: manifest_stt_plugin(&manifest), // helper: first STT stage plugin_id or None
    manifest_version: None,
    output_language: None,
};
if let Err(e) = history_backend.append(&history_entry).await {
    tracing::warn!(error = %e.message, "history write failed; continuing without persistence");
}
```

**Scope-Hinweis:** `manifest_stt_plugin()` und `manifest_stt_style()` sind private Hilfsfunktionen (nicht exported). Aus dem Manifest lesen:
- `plugin_id`: erste Stage mit `PipelineStageType::Stt { plugin_id }` → `Some(plugin_id.clone())`; sonst `None`
- `style`: erste Stage mit `PipelineStageType::Cleanup { plugin_id }` → `Some(plugin_id.clone())`; sonst `"verbatim".to_string()`

**Wichtig:** History-Persist passiert NUR auf `deliver()-success`-Pfad. Auf `deliver()-error`, `output-target-not-found`, leere Pipeline, STT-Error → KEIN History-Eintrag. (Entspricht architecture.md §Data-Flow: `OutputTarget → History-Persistence`.)

```rust
use klarvo_core::history::{HistoryBackend, HistoryEntry};
use klarvo_core::error::AppError;
use tauri::State;

/// Tauri-serializable projection of HistoryEntry.
/// `specta::Type` export erzeugt TypeScript-Interface für Story 9.3 (History-Panel).
#[derive(Debug, Clone, serde::Serialize, serde::Deserialize, specta::Type)]

    pub language: String,
    pub created_at: String,

    pub output_language: Option<String>,

pub async fn get_history(
    store: State<'_, std::sync::Arc<dyn HistoryBackend>>,
    limit: Option<u32>,

    store: State<'_, std::sync::Arc<dyn HistoryBackend>>,
```

### Wichtige Entscheidungen für den Dev Agent

**raw_text = None (Phase-1):** Die Pipeline returniert in `run_pipeline()` nur das finale `StageData::Text` (nach Cleanup). Der Roh-Transcript (prä-Cleanup) wird nicht separat tracked. `raw_text` bleibt `None` in Phase-1 — kein Pipeline-Umbau nötig.

**`app_name = None (Phase-1):`** HWND zu Process-Name (via `QueryFullProcessImageName`) wäre weiterer Win32-Call in `session.rs`. Phase-1: nicht implementiert, `None`.

**created_at ohne chrono:** Kein `chrono`-Dep im Workspace. Option A: `time`-Crate nutzen (transitiv via `tracing-appender`, kein neues Top-Level-Dep, aber Feature-Flag-Prüfung nötig). Option B: `std::time::SystemTime::now().duration_since(UNIX_EPOCH)` → Sek. → eigene minimalistische `format_utc_datetime(secs: u64) -> String`-Hilfsfunktion. Option B ist robuster (kein transitives-Dep-Risiko). Dev Agent wählt; der Ansatz muss idempotent + timezone-safe (UTC) sein.

**`rusqlite` auf Windows-Target:** `rusqlite` hat ein `bundled` feature das sqlite3 staticly linkt. Prüfen ob unter MinGW cross-compile das bundled-Feature nötig ist. Wenn `cc`-Crate Probleme macht → Hinweis in Dev-Notes des Story-Review.

**`HistoryBackend` Trait-Objekt in Tauri State:** Tauri `State<'_, Arc<dyn HistoryBackend>>` setzt voraus dass der Trait `Send + Sync + 'static` ist — das ist via Trait-Bound sichergestellt. Wenn Tauri-specta Schwierigkeiten mit trait-Objekt-State hat: Alternative ist `Arc<HistoryStoreWrapper>` als newtype, aber das sollte nicht nötig sein.

**Tokio-Mutex vs std::sync::Mutex in SqliteHistoryStore:** `rusqlite::Connection` ist nicht Send. Daher muss `SqliteHistoryStore` entweder:
- (A) `Arc<tokio::sync::Mutex<Connection>>` nutzen (Tokio-Mutex ist sicher in async-Kontext)
- (B) `Arc<std::sync::Mutex<Connection>>` + `spawn_blocking` für jeden DB-Call

Option A ist einfacher. Kurze non-blocking Lock-Sections für Insert/Select sind akzeptabel. Wenn `rusqlite::Connection` tatsächlich `!Send` ist (verifizieren: auf `Connection: Send` kompilieren), dann `spawn_blocking` nötig. Dev Agent soll kompilierbarkeit prüfen.
