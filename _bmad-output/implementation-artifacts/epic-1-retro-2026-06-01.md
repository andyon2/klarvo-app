## 2. What Went Well

1. **Root-cause architecture, not four spot-patches.** ADR-0015 recognized that ROB-01/02/04/05 share one missing convention. Four findings — incl. two critical — collapsed into one atomic-write helper + backup-on-corrupt + single-writer lock. The correct atomic pattern already existed in-tree (`llm_model.rs:250-256`); the epic generalized it.

2. **The team closed its own gap mid-sprint.** Story 1.3 distributed the disk-write lock as a hand-written pattern across 18 call sites. Review surfaced that this was *convention, not enforcement* — a dropped guard would not turn a test red. Rather than logging it for "later," **Story 4.3 was pulled forward** to extract a single `save_config_locked` choke-point where the lock cannot be gotten wrong at a call site. Convention → structural enforcement, applied within the epic.

3. **Reviews caught real issues, not cosmetics.** The honest-messaging fix in 1.4 (the migration-backup message overstated data loss — reworded, because keys/license are safe in *every* backup); the test de-tautologization in 1.3 (Spec B now observes the real disk lock) and 1.5 (now asserts the index is UNIQUE via PRAGMA + row survival, not just the index name).

4. **Calibrated distrust-escalation.** The Sonnet review of 1.4 was distrusted; an independent Opus 4.8 re-review found 3 further real patches plus the honest-messaging fix. Correct use of the model gradient on a critical-path review.

5. **Deferred-but-tracked discipline.** `deferred-work.md` holds every follow-up with source-ref + severity. Nothing was silently dropped; one item (D1) was already closed as 4.3.

## 3. Challenges

1. **Build-chain blind spot (Story 1.2) — the most dangerous moment.** The Windows smoke first ran a **stale binary**: the build had *silently* failed (`TAURI_SIGNING_PRIVATE_KEY` from `.env` + `createUpdaterArtifacts:true` → signer abort → no fresh artifact, but the old one remained). The smoke nearly passed against the wrong build — exactly the failure mode the manual-smoke DoD exists to prevent. Fixed via `createUpdaterArtifacts:false` + build-script gating.

2. **Call-site miscount (17 vs 18).** Story 1.3 hand-counted "17" config-save sites; 4.3 found 18. Not sloppiness — a symptom of `config/mod.rs` being the SHALLOW god-file (DEPTH-config). Hand-counting call sites in 2790 lines loses one. This is precisely what Epic 4 addresses.

3. **Test-binding gaps recurred (1.3 + 1.5).** Initial specs characterized patterns *inline* instead of binding to the real production paths; review patches were needed so a dropped guard / lost invariant turns tests red. Ironically the same "false-safety island" disease the audit flags as TEST-01..05 — it appeared in the team's *own* new tests. The review net caught it, but at review time, not at writing time.

4. **A DoD gate technically unmet.** The 1.4 `cargo check --target x86_64-pc-windows-gnu` gate could not run (no Windows target in WSL). Code is cross-platform, risk low, but the gate is open until the next real Windows build.

---

## 4. Key Insights (cross-story patterns)

- **The team is fighting the audit's disease in its own tests.** Test-tautology risk surfaced across 1.3 and 1.5 — the same false-safety pattern Epic 3 targets in the codebase. Lesson: bind specs to real production call sites at *writing* time, not just catch it in review.
- **God-file friction is real and measurable.** The 17-vs-18 miscount is a concrete cost of the un-decomposed `load_config` / `config/mod.rs`. Epic 4 (DEPTH-config) is validated by this.
- **Honest-messaging held twice.** 1.2's boot-toast ("best-effort, may be lost — the durable surface is the backup file") and 1.4's migration message (overstatement removed). The team resisted overclaiming under its own review.

## 6. Next Epic Preview — Epic 2: Android Security Guardians

**[Gated by ADR-0016 — Accepted]**

- **Dependency on Epic 1:** None. Independent Kotlin surface (epics.md: "Standalone: Yes — no dependency on Epic 1").
- **Class:** Entirely **surface-class** — real Android build + manual on-device test in the DoD (NFR-Smoke).

Plus the min-length/silence pre-filter, paste-text sanitization on all paths, and the banking-app blocklist on the paste path (not just the bubble). Findings: DIV-01/05, DIV-02, DIV-03, DIV-04.

**Carry-over lesson that bites hardest here:** the Story 1.2 stale-binary trap. On desktop it was a stale `.exe`; on Android the same trap is larger (old APK on device, Gradle cache, `installDebug` silently keeping the prior version). Epic 2's entire DoD rests on the manual on-device test running the *right* APK.
