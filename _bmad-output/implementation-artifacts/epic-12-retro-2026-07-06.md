## What & Why

Make the cloud pipeline resilient to provider failure: a robust STT/LLM fallback ladder, a
user-visible degrade signal in the pill, and an audio-retry history so a terminal failure never
means silent data loss. Closed with the **epic10×epic12 integration** — one line carrying the
native desktop overlays (Epic 10) *and* Epic 9/11/12, which required re-porting 12-1's pill-status
signal from the (deleted) WebView2 `FloatingBar.tsx` into `native_pill.rs`.

## What went well

1. **Observability-first beat guessing — twice.** The incident root cause (transport error ≠
   `ApiError` → fallback never fired) was *read* from the log, not speculated. Same for the overlay
   regression: `[fe:bar]` logs + window-enum proved "old WebView2 build", not a new bug.
2. **Extended the existing plumbing instead of rebuilding it.** `PipelineEvent::warn` already
   existed and was already emitted; 12-1 added call sites rather than duplicating the machinery
   (reduction before construction, cleanly lived).
3. **Device verification caught what code-review couldn't.** Android had *no* runtime fallback at
   all; the paste-toast overlapped the status-toast — both only visible on the real device.
4. **Forward-designed the primitive.** 12-2's `status`/`audio_path` schema carries 12-3 with no
   rebuild.
5. **The disjoint-history discovery** (main and the epic line share no merge base) prevented a
   destructive bad merge into `main` — surfaced before acting, not after.

## What was hard (the real lessons)

1. **Cross-platform twin drift is the dominant recurring cost — Andi's #1 frustration.** ~85% of
   Android reimplements the Rust dictation path in Kotlin; every fix lands twice with no SSOT.
   12-2's own audit even carried a *stale* twin claim ("Android has no savePendingWav") that was
   wrong at audit time and right at dev time — the twin state is genuinely hard to track. This,
   plus **the many device fix-rounds it forces**, was the epic's biggest tax. (Standing structural
   question — expand shared-core beyond STT — tracked via [[project_shared_core_is_stt_only]] /
   ADR-0016; not an Epic-12 action.)
2. **The regression was a process failure, not a compositing bug.** Overlay/product fixes were made
   on whatever branch was hot and never propagated to the canonical line → any build forking before
   the fix loses it. This integration heals the symptom; the root is branch hygiene → **new backlog
   action** (below).
3. **Verification-symmetry gap, recurring.** The outage test state is not UI-producible (key
   validation blocks invalid keys), so 12-1, 12-2, and the integration device-verify all required
   injecting an invalid key directly into `config.json`. A permanent test affordance would remove
   the friction each time.
4. **Windows compile feedback is slow.** Cross-compile fails on ONNX (`ort-sys`, no windows-gnu
   binaries), so the only Windows compile gate is the full PS release build — no fast local check
   for the `#[cfg(windows)]` paths (`native_pill.rs`, pipeline windows blocks).
