## 2. What Went Well

1. **Epic 1's process lessons transferred and paid off — the first proven learning transfer in the ledger.**
   AI-2 (bind tests to the real production call site, not an inline copy) is the *direct* reason review
   caught a 4th, story-missed unsanitized paste path in 2.3: `cleanupLocal` returned raw text on an MNN
   model-load failure **without throwing**, bypassing the wrapped `catch` straight to the clipboard. Bound
   against the real `KlarvoApi.sanitizeLlmOutput`, the leak turned a test red. Patch `dc377f3`.

2. **Reviews caught real leaks, not cosmetics.** 2.4: a missing `autoLoopActive=false` parity in the guard
   block — the sole terminal path that dropped it (`9c036b6`). 2.2: `computeWavRms` divided by the
   header-*claimed* sample count instead of the count actually read, plus a tautological threshold test that
   asserted nothing. Each was a genuine correctness/honesty fix, not a style nit.

3. **The surface-class DoD held.** A real Android build + manual on-device test gated every story.
   AI-1 (build-freshness) ran clean on all four smokes — the same stale-binary trap that nearly sank
   Epic 1's Story 1.2 (stale `.exe`) was avoided here, where it is *larger* (old APK on device, Gradle
   cache, `installDebug` silently keeping the prior version). Freshness was proven by the
   `scripts/android-build.sh` timestamp gate + the build-install act, not by a version number (the app has
   no in-UI version/About screen — the Epic-1 AI-1 wording was corrected accordingly).

## 3. Challenges

1. **Parity-by-copy is structurally fragile.** Android ports each guard as a hand-written copy of the Rust
   behavior at *N* call sites, where the desktop sanitizes once centrally (`pipeline.rs:1184`). The 2.3 leak
   (a 4th paste path forgotten) is **exactly what the Blind Hunter predicted** — per-branch wrapping invites
   the next raw-return path to be missed. The review net caught it, but the structure keeps generating the
   risk. Deferred fix: a single-egress sanitize chokepoint in `KlarvoOverlayService`.

2. **gen-mirror drift.** The gitignored build-target copy drifts from the canonical `android/kotlin-src/`
   source: 3 stray `[DIAG]` `Log.e` lines, and in 2.2 the GATE-2 canonical test was *gen-only / unversioned*
   (it would never have run in CI). A recurring hygiene risk of the Android two-copy topology. The mirror must
   be re-synced clean from source on each Android build.

3. **Test-tautology recurred on Android too (2.2).** The same false-safety disease seen in Epic 1's own new
   tests (1.3/1.5) reappeared in the Kotlin tests — AI-2's path-binding mitigates it, but a tautological
   threshold assertion still slipped through to review time. This is precisely the disease Epic 3 targets in
   the codebase, now confirmed to recur in newly-written tests when not actively guarded at writing time.

## 4. Key Insights (cross-story patterns)

- **Cross-platform drift is real and measurable, not theoretical.** Epic 2 produced concrete drift instances
  between the Rust core and the Kotlin port — `computeWavRms` divisor (header-claimed vs. read),
  `sampleCount==0` → NaN vs. `Some(0.0)`, and the `sanitizeLlmOutput` char-set held "in lockstep" only by
  hand. Combined with the pre-Epic-2 `759087f` silence-field divergence (Android read only
  `bubbleTapSilenceSecs`), this is a validated need for a **parity contract** — see Action Items.

- **ADR-0016 asserts parity but does not enforce it.** The parity mandate is real, but its enforcement is
  convention (a developer re-implements Rust logic in Kotlin). Nothing turns red when one side changes and
  the other does not. Operationalizing the mandate (golden vectors + config-key contract) is the missing
  piece — a candidate ADR-0016 amendment, not an Epic-3-scope story.

- **The Epic 1 → Epic 2 lesson transfer worked.** AI-1 and AI-2 were not just checked off; AI-2 *caught a
  leak that would otherwise have shipped*. The retro habit is paying compounding returns.
