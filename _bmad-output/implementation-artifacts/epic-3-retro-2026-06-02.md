## 2. The Headline Lesson (and it is uncomfortable)

**In ALL FOUR stories, review caught a *new* tautological false-safety construct — inside the very specs
written to eliminate false safety.**

- **3.1:** the stop-priority test was `let fired=false; assert!(!fired)` — it never called the seam. Deleted;
  stop-priority documented as a loop-ordering property out of the per-chunk seam's scope.
- **3.2:** `test_payload_no_dictation_sample_when_not_requested` built the payload by hand and never ran the
  gate. Worse, the **round-1 fix was itself insufficient** — the new wire tests bypassed the call-site binding;
  re-review caught it, round-2 corrected it (`send_feedback_inner` + wiremock specs that pass the flag *into* the seam).
- **3.4:** `spec_all_markers_present_always_fails` was tautological for AC-3 — with all N markers present, Fail
  holds at any threshold ≤ N, so it could never guard the `>=2` boundary. Replaced with an explicit
  two-marker boundary spec (`2→3` relaxation flips it red).
- **3.3:** comment-honesty patches + removal of the `insta` snapshot that pinned the *implementation* rather
  than the *specification*.

This is the same disease seen in Epic 1's own new tests (1.3 / 1.5) and Epic 2's Kotlin tests (2.2). The
durable finding: **writing real specs does not immunize against writing fake ones.** What caught it every
single time was not the writing — it was the **empirical inversion check at review time**: flip the invariant,
prove the test goes RED. That check is the one repeatable tool that worked across the entire epic, and across
the entire ledger.

## 3. What Went Well

1. **Epic 2's AI-1 (parity down-payment) was delivered in 3.3 and paid off.** The WAV-RMS vectors were authored
   as a language-neutral JSON fixture read at runtime by **both** the Rust parametric spec and the Kotlin
   `WavRmsVectorsTest` — the first real cross-platform parity contract, closing exactly the 2.2 `computeWavRms`
   divisor drift. The `insta` snapshot was removed in favor of closed-form asserts. F2 (the float32 Rust↔Kotlin
   asymmetry) was lifted into the fixture as first-class data (`expected_rms_kotlin: null` + `divergence_reason`)
   instead of being hidden in a hardcoded id-skip.

2. **Reviews found substance, not cosmetics.** Every fix-loop round closed a genuine honesty/correctness gap
   (the tautologies above, the insufficient round-1 wire binding in 3.2), not a style nit.

3. **Scope-fencing held cleanly.** "Pure test-integrity → no smoke owed" was applied with discipline across all
   four stories — no wasted Windows-build ceremony on test-only work, while the surface-class hard gate stayed
   intact for the stories that needed it (none here).

---

## 4. Challenges

1. **The inversion check is review-time, not writing-time.** It caught everything — but only after the fact.
   Every story spent a fix-loop round on it. That is recoverable waste: the check is mechanical and could run
   when the spec is authored, not when it is reviewed. (See AI-1.)

2. **Round-1 fixes can themselves be insufficient (3.2).** The first correction bypassed the call-site binding
   it was meant to add. Independent re-review is not optional — the `dev_story_commit_variance` lesson
   (re-review the diff independently, flip the gate to verify RED) held again.

## 7. Sprint Sequencing Decision — Epic 4 is next

**Decision (Andi, 2026-06-02): Epic 4 is the next sprint.** (First considered fencing it; reconsidered in
discussion and reversed — see the hinge below.)

The audit's risk findings (ROB / DIV / TEST) are all closed across Epics 1–3, so Epic 4 carries **zero
audit-risk value** — it is a pure behavior-preserving god-file refactor. The fence-it case was: no users
(Early Access withdrawn), no release pressure, lowest-priority churn risk.

**The hinge that flipped it: Andi plans continued work on this codebase — he personally wants many more
features.** Given that, Epic 4 is not a deferrable halde but **foundation**:
- 4.1 splits the ~290-LOC `load_config` god-function into a pure, unit-testable `migrate_and_normalize`, and
  **unlocks the deferred 1.3-D1** (compile-enforce the single-writer invariant).
- 4.2 tightens `pipeline.rs` contracts + demotes the test-only `pub` surface — exactly the file future feature
  work will live in.
- The Epic-1+3 test net is **fresh right now**, so refactor regressions get caught; doing it cold later means
  rebuilding that confidence.

**Therefore:**
- Epic 4 is the next sprint. Order: **4.1 first** (config split, 1.3-D1 unlock, ADR-0015 §5 linkage), then **4.2**
  (`pipeline.rs`; the more independently-deferrable of the two if a minimal scope is wanted). 4.3 already `done`.
- The remediation ledger stays **open** until Epic 4 closes; feature work follows after.
- Apply AI-1 (writing-time inversion check) to any new tests authored in 4.1/4.2.

No significant discoveries. No epic-planning review session needed.
