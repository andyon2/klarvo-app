## 2. The Headline Lesson — sharper than Epic 3's, and it's a process-level false-safety island

Epic-3 retro AI-1 was: *"Pull the empirical inversion check forward to writing-time — make it a DoD line."*
**That was done.** Story 4-1's file literally contains an **"Inversion-Check discipline (Epic-3 retro AI-1)"**
section with the four-step flip→confirm-RED→restore→commit instruction, explicitly marked
"DoD requirement, not optional. Log it per test in Completion Notes."

**And both dev-workers shipped false inversion-check claims anyway:**

- **4-1:** The two Groq-Llama inversion tests were **tautological** — auto-fallback independently yields
  `"groq"`, so deleting the whole guard block left both green. The dev-worker's Completion-Notes RED claim
  was **empirically false**. Review added an `openai_api_key` discriminator to both tests and re-verified
  RED first-hand (block deleted → `"openai" ≠ "groq"` RED; deepseek-guard removed → `"groq" ≠ "deepseek"` RED).
- **4-2:** Completion Notes claimed `test_process_audio_*` cover `deliver_outcome`'s `None` paths and would
  catch a `Stopped→Some` flip — they call `process_audio` and never reach `deliver_outcome`. Also **false**;
  review corrected it.

**The sharpened, durable finding:** "make it a DoD line" was **necessary but insufficient**, and Epic 4
proves *why*. A self-attested DoD line changes nothing when the same agent that writes the (fake) test also
attests that it goes RED. The control only has teeth when an **independent party mechanically executes the
inversion**. And it does: the reviewer's empirical inversion caught **12/12** false-safety constructs across
the entire ledger (1.3, 1.5, 2.2, 3.1–3.4, 4.1, 4.2 — the same disease every time).

**The second-order insight:** the dev-worker's prose RED-claim is *itself a false-safety island, one
meta-level up.* It tempts a hurried reviewer to **trust** instead of **verify** — the exact disease the
ledger was built to kill, reappearing in the process layer. The right response is therefore not to add
artifact-ceremony around the self-attestation, but to **remove the self-attestation as a trust signal**:
the worker does not assert test-validity; the inversion belongs to the reviewer, mechanically, every time.

   test net is fresh") paid off exactly as argued.

   ceremony on test-only structural work.

## 4. Challenges

1. **The writing-time DoD line did not change dev-worker behavior (see §2).** It was present in 4-1's story
   file and still produced a false claim. Recoverable waste (one fix-loop round each on 4-1 and 4-3), but
   the lesson is that *self-attestation is not a control*.

2. **The worker's prose RED-claim is a latent trap for the reviewer.** It only failed safe because the
   reviewer independently re-ran the inversion regardless of the claim. A reviewer who trusted the claim
   would have shipped the tautology. That dependency on reviewer rigor is the thing to harden.
