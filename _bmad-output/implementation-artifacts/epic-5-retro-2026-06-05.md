## 2. The Headline Result — Epic-4 AI-1 held, and it generalized

Epic-4's hardest-won lesson was: **the mechanical inversion belongs to the reviewer, not to the
worker's self-attestation; drop the prose RED-claim as a trust signal.** Epic 5 is the first epic
*after* that correction, and the correction landed cleanly:

- **Every** guard-spec inversion in Epic 5 was reviewer-/conductor-verified RED, explicitly logged
  as **"not self-attested"** (5-1 AC-2 marker-disable → `spec_delta_snapshot_disjoint_union` RED and
  AC-7 offline-guard-removed → `spec_preview_flush_guard_offline_stt` RED; 5-3 AC-5; 5-4
  flip `Some(3.5)→Some(3.0)`; 5-5 AC-2 `"wide" != "compact"`). No believed worker prose.
- **It generalized past test-specs.** In 5-1 the mechanical review caught a **false "clippy clean"
  self-claim** from the dev-worker (P4: a new `too_many_arguments` warning, 20→19). The
  self-attestation disease is not test-specific — the reviewer-as-verifier catches it on lint claims
  too. Exactly the generalization Epic-4 AI-1 predicted.

This is the cleanest possible follow-through: the most expensive lesson of the remediation ledger
transferred without loss to the first feature epic.

## 3. What Else Went Well

1. **Variant-B architecture carried the whole epic.** Preview = display-only, finish path
   byte-identical → no output regression path existed by construction. The riskiest part of a
   "live preview" (does it corrupt the paste?) was designed out before any code.

2. **5-4 came in clean (zero fix-loop rounds) and the deferral seam held.** Regler B was fully
   independent of 5-1–5-3 — it could have shipped, deferred, or been dropped without touching the
   preview. ADR-0016 parity was live-tested: both camelCase keys unchanged, no Android change, the
   `android_silence_field_divergence` guard honored.

3. **Mid-epic scope grew under control.** The 5-2 Windows smoke surfaced "the form should be
   selectable" → 5-5 was added *as a story over the epic* with its own ACs and FR (FR10), not
   improvised into 5-2. The default (`comfortable`) reproduces the shipped 5-2 look exactly → zero
   behavior change for the additive key.

4. **The Epic-4 foundation paid off.** 5-1 extended `pipeline.rs` in its now-navigable form; 5-3/5-4
   wrote through the single sanctioned `save_config_locked` choke-point (ADR-0015 / Story 4-3). The
   "refactor first so features live in clean files" bet (Epic-3 retro) is realized.

5. **A deliberate good-enough close on cosmetics (5-2).** Andi signed off "noch nicht perfekt, reicht
   aber für done" — a conscious product call for a *display-only orientation* feature, where residual
   pixel-polish carries no correctness risk. Healthy scoping, not a dropped gate.

## 4. Challenges — the surface-trap family

The durable finding of the first feature epic: **every functional bug surfaced only in the Windows
smoke and was green on Linux `cargo test` + `tsc`.** Five distinct traps, each shipped at least once:

1. **camelCase config key** (5-2): serde silently ignored snake_case `live_preview_enabled` → feature
   silently off → "no chunks" in the smoke. Doc bug + Andi's config flipped.
2. **f32 resync stuck-dirty** (5-3): a new float field not added to the `loadedSettings` resync
   `useEffect` left Save permanently dirty.
3. **FloatingBar separate-window non-remount** (5-5): mount-only `getSettings` froze the saved preset
   inert until app restart — all 3 review layers converged on this AC-4 gap.
4. **Window geometry / region clip** (5-2 hardcoded 200×36 region; 5-5 grow-upward resize race) —
   two smoke-fix rounds on 5-5 (r1 skip the pre-measure transient, r2 `geomTick` re-asserts geometry
   on cold first expansion).
5. **Event push-wiring** (5-1/5-2): colon-form `klarvo://live-preview-chunk`, push sink not poller.

This is the feature-surface analog of the ledger's false-safety island: a recurring **family of
platform-specific traps that only the Windows smoke catches**. The `project-context.md` rule
"Linux-green ≈ zero signal for surface stories" was vindicated hard. The corrective is AI-1 below.

A second, milder challenge: 5-2 and 5-5 each needed multiple smoke rounds for FloatingBar
geometry — expected for a separate Tauri window with dynamic content, but worth making mechanical so
the same clip class isn't rediscovered each time.
