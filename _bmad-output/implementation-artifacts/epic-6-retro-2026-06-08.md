## 2. Headline Result — the structural bet went through

The most expensive signal of the whole bar saga: **one design choice had five faces**
(R3/R4/R5/R6/R10/R11), and four point-fixes failed trying to make per-chunk async geometry atomic.
Epic 6 did not assert harder against the races — it **removed their producer**: no per-chunk window
IPC means the races *cannot* exist (NFR1, inversion-protected). This is the confirmation of the
Refactor→Re-design pivot, and it transferred without loss on the first try. Point-guards cannot make
an async-per-chunk geometry path atomic; a static-per-recording design makes the question moot.

## 3. What Else Went Well

1. **Epic-4/5 AI-1 (reviewer-mechanical-inversion) held again.** 6-2 mechanically caught a **false
   "clippy-clean" self-claim** from the dev-worker (same pattern as 5-1-P4); every guard-spec
   inversion was reviewer/conductor-verified RED, "not self-attested."
2. **Log-first discipline held under pressure (6-2).** The "no preview box" regression was diagnosed
   by **reading the console-bridge log** (capability listen-deny + tuple-serde NaN — two distinct
   Tauri platform traps), *after* a first elimination-guess (1×1 stub, 991c401) went wrong. Andi's
   "I am the test-machine" frustration was respected → durable memory
   `reference-tauri-capability-listen-and-tuple-serde`.
3. **Objective pixel metric over eyeballing (6-6 border-clip).** Teal-border px counted per edge via
   DPI-aware CDP capture; the inversion confirmed both the diagnosis and the fix (padding:0 →
   TOP/LEFT 100%, BOTTOM/RIGHT 0%; padding:2 → all four 100%). Exactly the
   `feedback-verify-surface-fix-with-objective-pixel-metric` rule; "never make the user the rendering
   oracle."
4. **Controlled scope growth (6-6).** Andi's real-build smoke showed the raw rgba/hex text inputs were
   *operationally dead* for a non-expert → conscious redesign to legible Themes/pickers/live-card.
   Lesson persisted to memory `feedback-surface-feature-operable-ux` (a customization surface must be
   *operable*, not a round-tripping raw-value field).
5. **6-5 smoke run mechanically from WSL** — the sharpest form of verification symmetry: the conductor
   proved the load-bearing "pill never resizes" claim itself (PrintWindow burst across all states),
   without handing Andi a non-producible eyeball test.

## 4. Challenges — and the gap this epic exposed

1. **6-2 cost the most** — a *wrong* elimination-guess (1×1 stub) before the log-driven real
   diagnosis. Two Tauri platform traps at once (capability `windows`-list + tuple→JS-array serde).
2. **6-6 had the longest tail** — three distinct smoke-fix rounds: (a) raw inputs unusable → redesign,
   (b) the **hook-forwarding bug** (Save reset *all* appearance to defaults), (c) DPI fractional
   border-clip.
3. **THE durable new finding — both automated reviews missed the 6-6 hook bug.** The save chain has a
   3rd hop (`SettingsPanel.onSave → useSettings.handleSaveSettings → saveSettings`);
   `handleSaveSettings` did not declare or forward the 7 appearance args → silently nulled → merge
   kept defaults. Both review layers verified the chain's **endpoints** (`SettingsPanel.onSave` +
   `saveSettings` signature) but **never traced the middle hop**, and Linux-green never sees it. This
   is a *new* surface-trap class — **multi-hop save/plumbing chains** — not previously on the
   `surface-smoke-checklist`. The checklist is only as good as its completeness.

**Pattern confirmation:** the surface-trap family persists — every functional Epic-6 bug still
surfaced only in the Windows smoke, green on Linux. The Epic-5 AI-1 checklist *anticipated* the known
classes but, being a check (not a guard), did not prevent the *new* class. The corrective is to grow
the ledger (AI-1 below).

## 8. Carry-Forward Technical Ledger (Epic 6 deferrals — all non-blocking)

From `deferred-work.md`, clustered. None block; all are opportunistic pulls:

- **Geometry / multi-monitor cluster (the dominant theme):**
  - 6-2: `monitorFromPoint` given logical px vs Tauri physical-coord resolution → wrong-monitor on
    HiDPI/multi-monitor (single-monitor @1.0 correct; `?? currentMonitor()` masks it).
  - 6-2: `room <= 0` floors `clampedMaxH` to 40 but `previewTop` may still overlap/clip when the pill
    sits near the screen top.
  - 6-3: card **width** never clamped to work-area; `wide`+`large` (~545px at k≈1.36) overflows a
    sub-545px work area (vertical axis is floored; horizontal has no counterpart).
  - 6-4: `cachedMonitorRef` not invalidated on a cross-monitor drag mid-recording (spec-sanctioned
    no-per-drag-IPC tradeoff, NFR1).
  - → If a multi-monitor / fractional-scale pass is ever scoped, these fold into one geometry-refine
    story with its own smoke.
- **Recovery-path cluster (shared with the bar, pre-existing):**
  - 6-1: `ensure_preview_window` recreate doesn't close the stale handle first → duplicate-label
    error in the rare "window exists but unresponsive" case. **`ensure_bar_window` has the identical
    pattern** — fix both together (`get_webview_window(label).map(|w| w.close())` before rebuild).
  - 6-1: `is_visible() Ok(false)` treated as "alive" → a hidden window is not re-shown by `ensure_*`
    (by-design probe; 6-2 shows on each chunk).
  - 6-1: click-through `set_ignore_cursor_events` fail-soft was flagged to "reconsider when 6.2 makes
    the window full-size" — **verify this was hardened** (a failed click-through now blocks the whole
    panel area, not a 1px trap).
- **Config-robustness cluster (hand-edit only, low):**
  - 6-6: R11 region/CSS corner-radius clamp asymmetry beyond UI bounds (radius >24, hand-edit only).
  - 6-6: `u8` preview numeric config (`previewBgBlur`/`previewBorderWidth`/`previewBorderRadius`)
    accepts 0–255 on deserialize with no on-load clamp.
- **Preview-flush residuals (carried from 5-1/5-7, retained in the new design):**
  - 5.1-C2 / 5-7: residual cross-recording bleed in the `isRecordingRef` stale-chunk guard (ref-guard
    chosen over session-token at the 5-7 gate); failed/empty flush after marker-advance drops a
    segment. Both very rare, orientation-only/throwaway preview. Full closure = backend
    recording-session id tagged on each chunk.
