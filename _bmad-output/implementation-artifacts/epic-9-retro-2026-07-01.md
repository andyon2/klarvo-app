## What went well

1. **Token codegen (9-10) — drift eliminated by construction.** `klarvo.css` → `KlarvoTheme.kt` generated with a `--check` gate; hand-drift is now structurally impossible. Same class of win as the Bar-Redesign "race gone by construction."
2. **Emulator became an honest window-STRUCTURE oracle (9-4 + 9-5).** After the conductor halt, we established that the emulator cannot honestly verify pixels/touch, but can reliably verify overlay window structure via `dumpsys window windows` + `DEBUG_SET_STATE`. This caught 9-5's double-window structurally — a harness gap turned into a real machine gate.
3. **Genuine infrastructure reuse (9-14 on 9-15).** HOLD built almost entirely on 9-15's `recordingButtonSizeDp` scaling + Settings round-trip rather than duplicating it — verified as "reuse, don't reinvent" in the story record.
4. **The final design convergence held** on the real device.

## What hurt — honest lessons

1. **Conductor halt mid-epic (2026-06-15).** Five seams tore at once: workers not committing, workers escaping to the real phone, no evidence, no lock, emulator false-green on real MIUI. Repaired (`conductor-guard.sh`, env guards, two-phase redesign). Root lesson stands: **visual epics are not honestly, fully-unattended verifiable.**
2. **Design-scale drift — the biggest product lesson.** The whole mobile overlay (HOLD/TAP/preview) was approved as *browser* mockups, never at device scale. Andi's thumb-test (9-14) rejected the lot as "too small / a laptop feature," forcing the full "B-Sprache" redesign with device-scale mockups. Two GATE-4 failures came directly from mockup-px treated as dp being too large at real device scale.
3. **9-7: auto-mode was broken on Android despite dev "done."** The device test — the actual deliverable of a verification story — had been rationalized away.
4. **Environmental friction:** HyperOS dims `FLAG_NOT_TOUCHABLE` overlays to alpha 0.8 (the "panel transparent" defect); STT-only shared-core means every design change double-touches the Rust↔Kotlin twins (~2000 LOC).

## Andi's assessment (Project Lead — verbatim signal)

- **Most valuable: "nothing comes to mind."** Recorded as data, not oversight. Epic 9 was a *catch-up* parity port; its value is external/invisible (cross-platform coherence). **Pure parity epics return little felt value to Andi while costing the same nudge-load.**
- **Most frustrating: the UI took a long time to become "good"/appealing, and the agents did not check this themselves enough — Andi had to keep nudging.**
- **Root not fully fixed; expects recurrence.** Device-scale mockups fix *scale*, not *aesthetic quality*. Quality still depends on how high the canon-approval bar is set.
- **Chosen framing (c):** aesthetics are inherently iterative. The realistic fix is to make the iteration **rounds cheaper**, not to avoid them.

### Structural finding

"Is this UI good/appealing?" is an aesthetic judgment — precisely the thing agents *cannot* do (Andi's eye is the oracle). Asking a build to self-converge visual quality asks for the one capability it lacks; the load therefore lands on Andi. The lever is not "agents check harder" — it is (a) front-loading the aesthetic decision into a genuinely-final, device-scale canon before any build, and (b) making each real-device iteration round cheap.
