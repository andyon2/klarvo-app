## 5. Things I suspected but could not confirm

Kept out of §2 on purpose — these are leads for the recall sweep, not claims.

1. **`System.loadLibrary` ordering for `GroqSttBridge`.** `BRIDGE:33-36` has an empty `init` and relies on the Tauri runtime having already loaded `libklarvo_lib.so`, unlike `LocalWhisperInference.kt:32-47` which loads it itself. If `KlarvoOverlayService` can start before the Tauri activity (boot-completed receiver, `DebugHarnessReceiver`, a restart by the system after a kill), every `nativeTranscribe`/`nativeSilenceCheck`/`nativeIsHallucination` call would throw `UnsatisfiedLinkError`. I could not find the `Application`-class load site. If the bridge can be reached cold, the *entire* shared STT path (and with it every "FIXED by consolidation" row above) has an unguarded precondition.
2. **Whether `ClipboardManager.setPrimaryClip` can throw at all** on the target devices. B30's "no detection" is certain; the consequence is not. If it throws, the throw happens inside the `handler.post{}` lambda (`KOS:2308-2391`), which runs on the main looper *after* the enclosing `try` at `KOS:2005` has returned — so `catch (e: IOException)` at `KOS:2393` cannot see it, and it would escape uncaught.
3. **The numeric threshold inside `VadSilero(Mode.NORMAL)`** (`KAR:411`). The `com.konovalov.vad.silero` dependency is not vendored, so I can state that Android has one threshold vs Desktop's 0.5/0.35 pair (B26) but not how far the single value sits from either.
4. **Android's SQLite journal mode / busy timeout.** Neither side sets `journal_mode` or `busy_timeout` (no PRAGMA in `HIST` or in the Kotlin), and on Android `history.db` has **two** writers — the long-lived Rust `Connection` (`lib.rs:755`) and per-call `SQLiteDatabase.openOrCreateDatabase` (`KAPI:626`, `:705`, `:740`). Whether a concurrent overlay write and a WebView-driven Rust write can collide (SQLITE_BUSY) depends on the default journal mode, which I could not establish from the tree.
5. **Whether `hound`'s WAV writer ever emits a trailing pad byte** for an odd sample count. If it does, Desktop WAVs would occasionally not match the canonical 44-byte layout that `compute_wav_duration_ms` (`GJ:61-73`) hardcodes. Today only Android WAVs reach that function, so it is latent at worst.
6. **`ListeningPanelView` appearance coverage.** I confirmed from the prop docs (`APPEAR:68-82`) and `SP:865-866` that `previewPanelForm` and `previewBgBlur` are deliberately hidden on Android, and that the remaining preview fields are read into `Config`. I did **not** read `ListeningPanelView.kt` line by line, so I cannot certify that *every* one of the eight remaining `preview*` fields is actually applied there — only that the controls are ungated and the values are parsed.
7. **Reachability of `llmProvider = "anthropic"` from today's UI.** The provider `KSelect` (`RA:145-151`) does not list it, but `SP:288-300` keeps `anthropic` in both the key map and the fallback search order, so a config that already names it survives a Settings visit. Whether any path still *writes* it (onboarding? an older build?) I did not trace.
8. **`bubbleTapSilenceSecs` in HOLD/TOGGLE.** B9 rests on `onSilenceDetected` being installed only for AUTOSTOP/AUTO (`KOS:1657-1661`). I did not exhaustively prove that `KlarvoAudioRecorder`'s `silenceSecs` has no *other* consumer besides `requiredSilentFrames` → `onSilenceDetected`; if it has one, the two keys are inert in a narrower sense than stated.
