## 4. Reader quality note

In this subsystem **A was the sharper reader on dead keys and B on React gates.** A got `previewBgBlur` and `localWhisperGpu` right where B waved both through as `ok` — and B's justification for `localWhisperGpu` ("effective only under the `cuda` feature") names a Cargo feature that does not exist, the one unsupported assertion I found on either side. Conversely B read the gate machinery properly (it spotted that `SETTINGS_CATEGORIES` sets no `desktopOnly`/`mobileOnly` flag and that the `AppearanceContent` docstring is therefore stale) and correctly placed the `hotkey`/`hotkeyMode` controls inside the `isDesktop` block, where A wrote "not rendered" — A's only outright wrong cell.

The systematic error pattern is shared and worth naming: **both readers treated a round-trip through `commands/settings.rs` / the `AppSettings` DTO as evidence of a "reader"** (B explicitly for `previewBgBlur`, A implicitly in several `ok` verdicts), and **both accepted in-code comments as ground truth** — A's "always-empty `llm_priority` post-migration" (the migration never clears it), B's `pasteDelayMs` "UI default 80" (that constant is a failed-load fallback, not a default), and neither noticed that `APPEAR:76-81` still claims Desktop applies the blur. Line numbers were accurate on both sides to within a few lines; B's were slightly more often exact.
