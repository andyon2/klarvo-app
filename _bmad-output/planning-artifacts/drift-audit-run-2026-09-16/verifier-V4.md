### 4. Reader quality note

Reader B was the more precise reader here: line numbers were within ±5 everywhere, the Hrana-body/`responseCode` analysis (B3), the ungated-toggle proof by JSX position (B10) and the `'T' > ' '` sort consequence (B34) all held up on the code. B's systematic weakness is treating code-level asymmetry as behavioural divergence without checking reachability — B16 ("Desktop pulls") and B33 (pending lifecycle) describe symmetric user-visible behaviour because `sync_history` has no UI caller and both platforms resolve pending entries from the same main-window card; B54 also got the cursor/HTTP ordering backwards. Reader A was sloppier on effects while right on locations: A34's "only in-app-button dictations" and the no-LLM-key row (`reader-A.md:205`) state consequences the code does not support, and A22 frames a live-vs-retry parity gap as a platform divergence. Both readers missed that Rust `open_db` runs on the shared Android `history.db` (softening B32) and that Voice Notes is hidden on both platforms (voiding half of B46); neither reported the local-cleanup silent-paste divergence (V-DLV-2) although it is already in the backlog.
